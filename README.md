# PhotoVedio:修圖與影片修復工具

用 Flutter 寫的手機修圖／修影片 App。所有處理都在手機上完成，不會上傳到任何伺服器：影片用 FFmpeg 解碼與編碼，畫面運算交給 OpenCV。
`python_engine/` 是同一套演算法的電腦版，用來開發、驗證演算法，也可以直接拿來處理影片。

## 功能

首頁有「修照片」「修影片」兩個入口，點了直接開相簿選檔。

### 照片
編輯畫面下方分成「濾鏡／調整／修復／裁切」四個分頁，一次只顯示一組工具，照片可以用雙指放大檢查細節。

- **濾鏡**：原圖、鮮豔、黑白、復古、冷色、暖色，用縮圖預覽效果
- **調整**：亮度、對比、飽和、銳化，數值以 -100～+100 顯示（雙擊滑桿可歸零）
- **提高畫質**：去除雜訊、讓輪廓更清楚，不改變色彩與亮度
- **除霧**：暗通道先驗除霧，可調強度
- **裁切**：自由、1:1、4:3、3:4、16:9、9:16
- **按住右下角的比較鈕（或長按畫面）看原圖**，方便前後比較
- **重設**後可以從提示列「復原」；有未儲存的編輯時，離開前會先確認
- **預覽和存檔一致**：
  - 預覽最後顯示的是原尺寸的處理結果，存檔時直接沿用，不會重算。
  - 長邊超過 5000 像素的照片，開啟提高畫質或除霧時會先縮小，避免手機記憶體不足；儲存時會提示縮小後的尺寸。

### 影片
- **提高畫質**（弱／中／強）
  - 先去除壓縮雜訊再銳化輪廓；降噪強度依影片的壓縮程度（位元率）自動調整。
  - 每格只要十幾毫秒，幾乎不增加處理時間。
- **除霧**：只在有明顯霧氣時使用，否則會改變原片色調。
- **AI 放大到 4K**（Real-ESRGAN）：放大 4 倍後縮到長邊 3840，補出細節、清掉壓縮雜訊，適合解析度低或被通訊軟體壓縮過的影片。
  - 非常耗運算：每個輸入像素約 240 萬次浮點運算，592×1280 的影格約 1.8 TFLOP。手機上會優先用 GPU/NPU（Android NNAPI、iPhone CoreML），不支援時退回 CPU。
  - 實測（4 核心 CPU、onnxruntime）：592×1280 每格約 11 秒。有獨立顯示卡的電腦會快很多，長影片建議用電腦版。
  - 開啟時取代「提高畫質」；皮膚等平滑區域會被抹得比較乾淨。
- **防手震**
  - **標準**：畫面裁切約 3～5%。
  - **強**：適合走路拍攝，裁切約 5～8%。
  - **超強**：晃動很大或跟拍時用，裁切約 8～12%。
  - **鎖定**：像架在腳架上，完全不晃；需要裁切太多時自動改用「超強」。
  - 會自動偵測晃動程度，畫面本來就很穩定時不處理。處理完會告訴你實際做了什麼、裁切了多少。
  - **含果凍效應修正**：見下方〈演算法說明〉。
  - **補邊**：修正後露出的邊緣用前後格的真實畫面補上，不必靠放大裁掉，所以能修正更大的晃動、畫面也保留更多。
- **HDR 影片**：iPhone 錄的 HLG／PQ 影片會輸出 10-bit HEVC，並保留色彩標註，播放時不會偏暗或變色。
- 處理時顯示目前步驟、百分比和預估剩餘時間，可以隨時**取消**。
- 處理完用「原片／處理後」切換比較，切換時停在同一個時間點；點畫面播放／暫停，可拖動進度條。
- 保留原影片的音軌；處理結果還沒儲存就離開時會先確認。
- 如果 App 在處理中被系統關掉（通常是記憶體不足），下次打開影片頁會顯示當時停在哪一步、用了多少記憶體。

## 演算法說明

### 防手震
1. **估計運動**
   - 相鄰兩格用特徵點光流（Lucas–Kanade）配對，RANSAC 排除移動中的人、車。
   - 再用最小平方法解出繞畫面中心的平移與旋轉。
   - 分析在約 720p 的縮小灰階影格上進行，4K 影片也很快。
2. **規劃平滑路徑**
   - 在裁切上限內反覆「高斯平滑 → 夾回上限」，找出最平滑、又不超出裁切範圍的鏡頭路徑。
   - 平滑的時間尺度依幀率換算，約 0.27 秒。
3. **鎖定模式**
   - 用 0～3 次多項式擬合整段鏡頭路徑：固定不動、等速運鏡或曲線運鏡。
   - 選需要裁切最少的一種。
4. **套用修正**
   - 以 Lanczos 取樣重新取像，並放大剛好蓋住黑邊的倍率（取 99 百分位）。

### 補邊（減少裁切）
防手震修正後，畫面邊緣會露出原影格沒拍到的地方。傳統做法是放大到完全蓋住，晃得越大裁得越多。
- 改為只放大約三成需要的倍率，其餘露出的邊緣，從前後 15 格（4K 時自動減少，控制記憶體）把真實畫面畫到目前格的穩定座標後補上。
- 只對露出的邊緣帶運算，不是整張畫面；前後格都補不到的少數像素（實測平均約 0.2%）才延伸邊緣。
- 因為不必靠裁切，修正上限可以大幅提高。以一段 42 秒手持跟拍實測：

| 強度 | 每邊修正上限 | 殘餘晃動 | 放大（不補邊 → 補邊） |
|---|---|---|---|
| 標準 | 5% | 4.95px | 1.16 → 1.05 |
| 強 | 8% | 3.59px | 1.23 → 1.07 |
| 超強 | 16% | 1.43px | 1.37 → 1.11 |

- 剛好在畫面邊緣移動的人，補上去時可能有些微錯位。電腦版可用 `--no-fill` 改回放大到完全蓋住。

### 果凍效應（捲簾快門）修正
手機感光元件是由上往下逐行讀出的，同一格的上下兩端拍攝時間相差約一格。手在抖的時候，畫面各部分的位移不同，看起來像果凍在晃。

- 把畫面切成 8 條水平帶，和整體平移、旋轉放進**同一個最小平方模型**一起解。
  - 條帶總和為 0，相鄰條帶平滑，並用 Huber 權重排除錯誤配對。
  - 分開估計時，果凍的錯位會被誤判成旋轉；一起解才分得開。
- 各條帶的偏移累加後做約 0.5 秒的高通，只修正快速的扭曲；慢慢運鏡造成的自然傾斜保留不動。
- 套用時每 16 列為一段，修正量在條帶中心之間線性內插，不會出現接縫。

合成測試（9～17Hz 手震、讀出時間 80%）：

| | 抖動 | 果凍扭曲 |
|---|---|---|
| 原片 | 3.6px | 3.6px |
| 處理後 | 0.38px | 0.38px |

### AI 超解析度
- 模型：Real-ESRGAN `realesr-general-x4v3`（SRVGGNetCompact，120 萬參數，BSD 3-Clause，授權見 `assets/models/LICENSE-Real-ESRGAN.txt`）。
- `python_engine/convert_sr_model.py` 不需要 PyTorch 就能把官方 `.pth` 權重轉成 ONNX；轉好的模型放在 `assets/models/`，App 與電腦版共用。
- 大畫面分塊處理，每塊多取 40 像素重疊（大於網路的作用範圍），結果與整張處理完全相同。
- App（Dart，onnxruntime）與電腦版（Python）的輸出最大差 1 個灰階（四捨五入誤差）。

### 提高畫質
手機影片（尤其是轉傳過的）最大的問題是壓縮造成的方塊、蚊狀雜訊和色塊，直接加強細節會連雜訊一起放大。
- 先用雙邊濾波（保留邊緣的平滑）去掉壓縮雜訊，再用反銳化遮罩讓輪廓清楚。
- **降噪強度依壓縮程度自動調整**：由位元率估計（每像素分到幾個位元，HEVC 換算成 H.264 等級）。轉傳過的影片約 0.1 bpp，處理較強；iPhone 原檔約 0.4 bpp，只輕微處理，不會抹掉真正的細紋。
- 實測（乾淨畫面經 H.264 重度壓縮，SSIM 越高越接近壓縮前）：不處理 0.9557、舊版細節增強 0.9443、目前的做法 0.9572～0.9588。
- 全部在 8 位元影像上運算，592×1280 每格約十幾毫秒。

### 除霧
- 暗通道先驗（He et al. 2009），透射率用導向濾波貼合邊緣。
- 大氣光與亮度補償會隨時間平滑，避免閃爍。
- 色度大部分沿用原片，最後再把亮度分佈拉回原片，色調不會跑掉。

## 專案結構

```
lib/
  main.dart              App 與首頁
  photo_page.dart        照片編輯頁(濾鏡、調整、修復、裁切)
  video_page.dart        影片修復頁
  engine/
    pipeline.dart        影片處理流程:FFmpeg 解碼 → 背景 isolate 用 OpenCV 處理 → FFmpeg 編碼
    algorithms.dart      影像演算法(運動估計、除霧、提高畫質、色調錨定、套用防手震)
    trajectory.dart      鏡頭路徑計算(平滑、鎖定、果凍偏移;純 Dart,不依賴 OpenCV)
    photo.dart           照片的除霧/提高畫質
    superres.dart        AI 超解析度(onnxruntime)
assets/models/           AI 超解析度模型與授權
  smoke_main.dart        實機驗證用入口(影片)
  photo_smoke_main.dart  實機驗證用入口(照片)
test/                    單元測試
python_engine/           電腦版演算法與驗證工具(與 lib/engine 逐函式對應)
```

`lib/engine/` 和 `python_engine/algorithms.py` 的演算法是一對一對應的。修改其中一邊時，請同步修改另一邊。`trajectory.dart` 是純 Dart，可以直接和 Python 版對照數值。

## 開發

需要支援 Dart 3.11 以上的 Flutter（見 `pubspec.yaml`）。

```bash
flutter pub get
flutter run            # 連接手機後執行
flutter analyze
# test/superres_test.dart 需要 onnxruntime 原生函式庫(套件內附 Linux 版):
LD_LIBRARY_PATH=~/.pub-cache/hosted/pub.dev/onnxruntime-1.4.1/linux flutter test
```

- 影片處理使用 `ffmpeg_kit_min_gpl`，支援 Android、iOS、macOS。
- 照片功能各平台都能用。桌面版沒有相簿，照片會存到「文件」資料夾。
- 第一次建置時，`opencv_dart` 會下載並編譯 OpenCV，需要一段時間。

## 電腦版（python_engine）

```bash
pip install opencv-python numpy imageio-ffmpeg onnxruntime   # 有 NVIDIA 顯示卡可改裝 onnxruntime-gpu
cd python_engine

# 和 App 相同的完整流程(原生解析度、支援 HDR)
python process_hdr.py 原片.mp4 輸出.mp4              # 標準防手震
python process_hdr.py 原片.mp4 輸出.mp4 --strong     # 強力防手震
python process_hdr.py 原片.mp4 輸出.mp4 --extreme    # 超強防手震
python process_hdr.py 原片.mp4 輸出.mp4 --lock       # 鏡頭鎖定
python process_hdr.py 原片.mp4 輸出.mp4 --extreme --sr   # 加上 AI 放大到 4K(長邊 3840,可指定:--sr 2560)

# 自選處理項目
python cli.py 原片.mp4 輸出.mp4 --stabilize --stabilize-level strong --enhance --enhance-level high --dehaze

# 驗證工具
python test_synthetic.py                          # 合成晃動 + 霧,驗證防手震與除霧
python verify.py 原片.mp4 成品.mp4 對比圖.jpg       # 比較亮度、對比、飽和度(HDR 先色調映射)
python quality.py 原片.mp4 秒數 成品.mp4 秒數 裁切.jpg  # 比較 PSNR 與細節量
python ab_test.py 影片.mp4 秒數 輸出.jpg            # 同一格處理前後的局部放大對比
```

## 已知限制
- 防手震只修正平移和旋轉，不處理前後移動造成的透視變化。
- 果凍效應修正針對逐行讀出造成的水平與垂直錯位，非常劇烈的震動仍可能有殘留。
- 影片處理時要停留在 App 內，切到背景可能被系統中斷。
- 4K 影片目前用原解析度處理，記憶體較少的手機可能不夠用。
